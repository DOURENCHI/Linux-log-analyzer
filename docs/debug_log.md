## 待改进 · 报告路径硬编码在 main() 里

**现象**

```cpp
if (!saveReport("reports/analysis_report.txt", stats))
```

路径写死在 `main()` 中。

**原因**

最初实现时只考虑"能跑通"，没有把输出位置参数化。

**影响**

- 无法指定别的输出位置（比如按日期命名、输出到 `/tmp`）
- `reports/` 目录不存在时，`ofstream` 打开失败 → 直接 `return 1`

**建议**

1. 加一个可选参数 `--out <path>`，缺省值保持现在的路径
2. 或在 `saveReport` 里对父目录做 `std::filesystem::create_directories`

C++17 已有 `<filesystem>`，后者只需两行。

**现状**

⚠️ 待改进（功能可用，但灵活性不足）

## 待改进 · tests/ 目录为空，没有自动化测试

**现象**

`tests/` 目录存在但没有任何文件。

**原因**

项目创建时预留了目录，测试还没有补上。

**影响**

改动 `parseLine` 的判断顺序、或 `matchesTimeRange` 的边界条件时，
只能靠手工跑 `logs/sample.log` 观察，**回归风险高**。

**建议**

至少补三类用例：

| 用例 | 验证点 |
|---|---|
| `isValidTime` | `"23:59:59"` 通过、`"24:00:00"` 拒绝、`"9:5:3"` 拒绝、`"ab:cd:ef"` 拒绝 |
| `matchesTimeRange` | 起止边界是否**闭区间**、格式不符的行是否被跳过 |
| `parseLine` | 空行 / 带前导空格的行 / 关键词两侧带空格是否生效 |

**现状**

⚠️ 待改进（最大的工程缺口）

**现象**

`#include <ostream>` 放在第 132 行，紧挨着 `writeReport` 的定义。

**原因**

写 `writeReport` 时才发现需要这个头文件，就地补上了。

**影响**

**现状**

⚠️ 待改进（纯风格问题，无功能影响）

## 已知边界 · 关键词用 `-` 当"不过滤"占位符

**现象**

```cpp
if (keyword.empty() || keyword == "-") return true;
```

`-` 被约定为"跳过关键词过滤"。

**原因**

命令行里想传第 4、5 个参数（起止时间），必须也传第 3 个（关键词）。
需要一个占位符。

**影响**

如果日志里确实想搜索 `-` 这个字符，这条路走不通。

**建议**

改成长选项风格：`--time 09:00:00 10:00:00`，
让"要不要关键词"由**选项是否存在**决定，而不是靠占位符。

**现状**

⚠️ 已知边界（当前功能范围内可接受）

## 已知边界 · 时间比较依赖"定长补零"格式

**现象**

```cpp
return logTime >= startTime && logTime <= endTime;   // 字符串比较
```

**原因**

`HH:MM:SS` 定长且补零，字典序与时间序一致，可以省掉解析成整数的开销。

**影响**

一旦日志的时间格式变成 `9:5:3` 或带毫秒（`09:05:03.123`），
字符串比较就会给出错误结果——**而且不会报错，只是结果悄悄不对**。

**建议**

在 `matchesTimeRange` 里加一条断言式的格式检查（长度必须正好 8），
或在注释里明确写出这个前提。

**现状**

⚠️ 已知边界（当前 `sample.log` 格式满足前提）

## 已知边界 · 级别判断靠子串匹配

**现象**

```cpp
line.find(" INFO ") != std::string::npos
```

**原因**

不解析完整日志格式，只用"两侧带空格的级别词"做子串匹配，实现最简单。

**影响**

| 情况 | 结果 |
|---|---|
| 日志内容是 `... INFO ...` | ✅ 正确识别 |
| 内容是 `PREFINFO` | ✅ 不误匹配（两侧无空格） |
| 级别写成 `[INFO]` | ❌ 识别成 Unknown |
| 一行同时含 `INFO` 和 `ERROR` | ⚠️ 只算 INFO（`else if` 顺序决定） |

**建议**

先用正则（`std::regex`）或按分隔符切分出"级别字段"，再判等。
代价是性能下降，但对小型日志文件无所谓。

**现状**

⚠️ 已知边界（够用，但换数据源要重新验证）
